D1认识与选型:standalone / 主从 / 哨兵

Bitnami Redis Chart 一个 architecture 字段切换三种形态:

architecture形态自动故障切换适用
standalone单实例—缓存/会话(Pod 挂了 K8s 拉起,数据在 PVC 不丢)
★ replication(本文)1 主 + N 从,异步复制无(从可读,主挂需人工切换)读写分离 + 热备
replication + sentinel主从 + 哨兵 3 节点有(哨兵选主)要自动切换;客户端须支持 sentinel 协议
⚠️ 先想清楚 Redis 的定位:① 当纯缓存 → standalone 就够,挂了重启数据从 DB 回填,别过度设计;② 当数据存储(队列/计数器) → 必须主从+持久化(RDB+AOF)+备份。Redis 的数据丢了能不能接受,决定一切选型。

D2版本锚定与离线准备(★bitnamilegacy 坑)

# 开发机:
helm repo add bitnami https://charts.bitnami.com/bitnami && helm repo update
helm search repo bitnami/redis --versions | head -6
# 选 APP VERSION = 7.2.x(与现网对齐;7.x 系最后一个 chart 锁定它)
helm pull bitnami/redis --version 20.6.0                # 得 redis-20.6.0.tgz

# ★Bitnami 2025-08 迁移坑(同 k8s-mysql.html M3 实测):
#   docker.io/bitnami/* 免费镜像已清空归档到 bitnamilegacy —— image.repository 必须改!
curl -s 'https://hub.docker.com/v2/repositories/bitnamilegacy/redis/tags/?name=7.2&page_size=10' \
  | grep -o '"name":"[^"]*"' | head -3          # 有输出 = 该 tag 存在,照抄最精确的

# 镜像清单 + 离线四连(同 07 章套路):
helm template redis ./redis-20.6.0.tgz -n redis -f values-redis.yaml \
  | grep -oP 'image:\s*\K\S+' | tr -d '"' | sort -u
docker save -o redis-images.tar bitnamilegacy/redis:7.2.x-debian-12-rX ...
scp redis-20.6.0.tgz redis-images.tar root@10.18.51.120:/root/k8s-install/pca/
ctr -n k8s.io images import redis-images.tar
helm install redis ./redis-20.6.0.tgz -n redis --create-namespace -f values-redis.yaml

D3values 配置全文(1主1从)

cat > values-redis.yaml <<'EOF'
architecture: replication
auth:
  password: "Redis-Prod-2026"        # 生产走 existingSecret 引用 K8s Secret
master:
  count: 1
  persistence:
    enabled: true
    storageClass: longhorn           # ★本集群存储类
    size: 8Gi
  disableCommands: ["FLUSHALL"]      # 禁全清防手滑(FLUSHDB 按需加)
  resources:
    requests: {cpu: 100m, memory: 128Mi}
    limits:   {memory: 1Gi}          # ★maxmemory 与 limits 配套设,防 OOM
  extraFlags:
    - "--maxmemory 768mb"
    - "--maxmemory-policy allkeys-lru"   # 缓存场景逐出;数据场景用 noeviction
replica:
  replicaCount: 1
  persistence:
    enabled: true
    storageClass: longhorn
    size: 8Gi
image:
  repository: bitnamilegacy/redis    # ★迁移坑,不改必 ImagePullBackOff
  tag: 7.2.7-debian-12-r0           # 以 D2 查到的精确 tag 为准
metrics:
  enabled: true                      # 开 exporter,接 07 章监控(ServiceMonitor)
EOF

D4安装与验证(PING / INFO)

kubectl -n redis get pods -w               # redis-master-0 + redis-replicas-0 全 Running

PW=Redis-Prod-2026
# 连通性(期望 PONG)
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" ping

# 主从状态(主上:role:master, connected_slaves:1)
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" info replication | head -6

# ★从库必须看到 master_link_status:up 才算复制打通
kubectl -n redis exec redis-replicas-0 -- redis-cli -a "$PW" info replication | grep -E "role|master_link"

# 快速功能自测:主写 → 从读
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" set linktest ok
kubectl -n redis exec redis-replicas-0 -- redis-cli -a "$PW" get linktest   # → "ok"

D5日常运维命令速查

# ── 扩容读副本(1 → 2,rolling 自动加 Pod)──
helm upgrade redis ./redis-20.6.0.tgz -n redis -f values-redis.yaml --set replica.replicaCount=2

# ── 密码轮转(values 改 + upgrade,StatefulSet 滚动;客户端连接串同步改)──
helm upgrade redis ./redis-20.6.0.tgz -n redis -f values-redis.yaml --set auth.password=New-Pass-2027

# ── 常用体检命令 ──
PW=Redis-Prod-2026
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" info memory | head -8    # 内存水位
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" dbsize                    # 键总量
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" slowlog get 5             # 慢查询
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" --bigkeys                 # 大 key 扫描
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" info stats | grep -E "keys|hit"  # 命中率

D6备份与监控接入

# ── RDB 手动备份 + 异机取回 ──
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" bgsave
kubectl -n redis exec redis-master-0 -- redis-cli -a "$PW" lastsave          # 时间戳确认
kubectl -n redis cp redis-master-0:/data/dump.rdb ./redis-dump_$(date +%F).rdb

# ── 监控接入(values 里 metrics.enabled=true 已起 exporter)──
kubectl -n redis get svc | grep metrics            # redis-metrics:9121
# 补一个 ServiceMonitor 即被 07 章 kube-prometheus-stack 采集:
cat >> sm-redis.yaml <<'EOF'
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata: {name: redis, namespace: prometheus, labels: {release: prometheus}}
spec:
  selector: {matchLabels: {app.kubernetes.io/name: redis}}
  endpoints: [{port: metrics, interval: 30s}]
EOF
kubectl apply -f sm-redis.yaml
💡 缓存库的备份哲学:纯缓存可不备份(冷启动回填);当数据存储用则 RDB+AOF 双开(appendonly yes 进 extraFlags)+ 定期 bgsave 取回,并纳入 7.13 告警链路(内存/主从断连告警)。
