J1认识与选型:Master + 动态 Agent

Jenkins 跑在 K8s 上的正确姿势是 Master 常驻 Pod + Agent 按需起 Pod(Kubernetes plugin 内置):任务来了才拉起 agent 容器,跑完即销毁 —— 不占常驻资源、天然隔离、并发随便开:

Jenkins Master(controller,StatefulSet×1,PVC 存 jenkins_home)
   │  收到 Job → 按 Pod Template 动态创建 agent Pod(maven/jnode/dind 等按需镜像)
   ├──▶ agent-pod-abc123(Job1:maven 构建)── 跑完销毁
   └──▶ agent-pod-xyz789(Job2:docker 打包)── 跑完销毁
形态资源适用
★ jenkins/jenkins Chart + 动态 Agent(本文)Master 2C4G 起步,agent 按需标准 CI,构建量大
Master + 固定 agent(物理机/虚机)—构建环境特殊(需 GPU/本地缓存)时补充
💡 与 GitLab CI 的分工(本站生态):GitLab 存代码(见 GitLab 篇),Jenkins 负责复杂流水线(多阶段审批、跨仓库、遗留脚本),二者通过 webhook/多分支流水线协作;纯 GitLab 体系也可只用 gitlab-runner。

J2版本锚定与离线准备

# 开发机:加仓库、锁 LTS 版本、下 tgz
helm repo add jenkins https://charts.jenkins.io && helm repo update
helm search repo jenkins/jenkins --versions | head -5
# Jenkins 版本规则:每 12 周一个 LTS(如 2.462.3);chart 5.x 配 Jenkins 2.4xx —— 锁 LTS 别用 weekly
helm pull jenkins/jenkins --version 5.8.1               # 得 jenkins-5.8.1.tgz

# 镜像清单(controller 1 个;agent 镜像按构建需要另备 maven/node/dind 等)
helm template jenkins ./jenkins-5.8.1.tgz -n jenkins -f values-jenkins.yaml \
  | grep -oP 'image:\s*\K\S+' | tr -d '"' | sort -u

# 离线四连(同 07 章套路):
docker save -o jenkins-images.tar jenkins/jenkins:2.462.3-jdk17 ...
scp jenkins-5.8.1.tgz jenkins-images.tar root@10.18.51.120:/root/k8s-install/pca/
ctr -n k8s.io images import jenkins-images.tar
helm install jenkins ./jenkins-5.8.1.tgz -n jenkins --create-namespace -f values-jenkins.yaml
⚠️ 离线最大的坑 = 插件:chart 默认在首启时联网下载 installPlugins 列表 —— 离线集群必卡死。解法见 J7(开发机 jenkins-plugin-cli 预下载 → 打进 PVC/initContainer 挂载),values 里务必锁死插件版本号。

J3values 配置全文

cat > values-jenkins.yaml <<'EOF'
controller:
  image:
    tag: "2.462.3-jdk17"            # ★锁 LTS
  serviceType: NodePort
  nodePort: 32080                   # 快速入口(正式走 ingress 也可)
  jenkinsUrl: http://jenkins.fftaicorp.com
  installPlugins:                   # ★全部锁版本(离线预置见 J7)
    - kubernetes:4285.v50ed5de9a_366
    - workflow-aggregator:596.v8c21c963d92d
    - workflow-job:1400.v7fd111b_on65f
    - credentials-binding:681.vf91669a_32e45
    - git:5.5.1
    - configuration-as-code:1836.vccda_4a_122a_a_e
  resources:
    requests: {cpu: 500m, memory: 1Gi}
    limits:   {cpu: "2",  memory: 4Gi}
  JCasC:
    configScripts:
      welcome-message: |
        jenkins:
          systemMessage: "new-k8s CI Server"
persistence:
  enabled: true
  storageClass: longhorn            # ★jenkins_home(任务/凭据/插件)全在这
  size: 20Gi
agent:
  enabled: true                     # 动态 agent(Kubernetes plugin 内置)
  podName: "default"
  customJenkinsLabels:
    - "build"
EOF
💡 一切配置即代码(JCasC):界面里点出来的设置重启不丢的原因全在 jenkins_home/casc;values 里能写的别去 UI 点,升级/迁移才可复现。

J4安装与初始密码

helm install jenkins ./jenkins-5.8.1.tgz -n jenkins --create-namespace -f values-jenkins.yaml
kubectl -n jenkins get pods -w              # jenkins-0 1/1 Running 即就绪

# ★初始 admin 密码(装完立刻取,首登后建议改掉)
kubectl -n jenkins exec jenkins-0 -c jenkins -- cat /var/jenkins_home/secrets/initialAdminPassword

# 预设方式(values 里写死,免"取密码"一步):
#   controller.admin.username: admin
#   controller.admin.password: Jenkins-Prod-2026     (生产走 existingSecret)

kubectl -n jenkins get svc                   # jenkins 32080 即 NodePort 入口

J5访问入口与首登

# 快速入口:任意节点 IP:32080(NodePort)
curl -I http://10.18.51.120:32080/login          # 200 即通
# 正式入口:改 ClusterIP + Ingress + 外层 nginx 反代(套路同 GitLab G5,换域名即可)
  • 首登:admin + initialAdminPassword → 插件选择页离线环境直接点 "Select plugins to install" 的关闭/Skip(联网下载必卡死)。
  • 进去第一件事:改 admin 密码(System → Security)。

J6日常运维命令速查

# ── 升级(锁 LTS 同系)/ 滚动重启 ──
helm upgrade jenkins ./jenkins-5.8.1.tgz -n jenkins -f values-jenkins.yaml
kubectl -n jenkins rollout status sts jenkins
kubectl -n jenkins rollout restart sts jenkins

# ── 备份 = 备 jenkins_home(任务/凭据/插件/配置全在这一个 PVC)──
kubectl -n jenkins get pvc
kubectl -n jenkins cp jenkins-0:/var/jenkins_home ./jenkins_home_$(date +%F) -c jenkins
#   (或 Longhorn 卷快照/Retrospect 备份;恢复 = 反向 cp 回去重启)

# ── 状态观察 ──
kubectl -n jenkins logs jenkins-0 -c jenkins --tail=100
kubectl top pod -n jenkins

# ── 动态 agent 验证:跑一个任务时盯住 ──
kubectl -n jenkins get pods -w
#   build-agent-xxx 起来 → 跑完 Terminating 消失 = 动态调度正常

# ── 凭据/任务都在 PVC 里,灾难恢复 = 新集群 + 原 PVC + 同版本 chart 重新 install ──

J7排障速查(含离线插件预置法)

离线预置插件(核心坑,开发机做一次)

# 1) plugins.txt(与 values 里 installPlugins 一致,全部锁版本)
cat > plugins.txt <<'EOF'
kubernetes:4285.v50ed5de9a_366
workflow-aggregator:596.v8c21c963d92d
git:5.5.1
configuration-as-code:1836.vccda_4a_122a_a_e
EOF
# 2) 用官方镜像内置的 jenkins-plugin-cli 预下载(开发机有网)
docker run --rm -v "$PWD:/ref" jenkins/jenkins:2.462.3-jdk17 \
  jenkins-plugin-cli --plugin-file /ref/plugins.txt -d /ref/plugins
# 3) 两种落地:
#    a. 自建镜像 FROM jenkins/jenkins:2.462.3-jdk17 + COPY plugins/ /var/jenkins_home/plugins/(推荐)
#    b. 直连救急:kubectl -n jenkins cp ./plugins jenkins-0:/var/jenkins_home/ -c jenkins 后重启 StatefulSet
症状真因处置
首启卡 Getting Started联网下载插件超时离线必现 → J7 预置法;已卡的 Pod 删掉重建
PVC PendingstorageClass 拼错/容量超限kubectl get sc 核对
agent Pod 起不来默认 ServiceAccount 无权限/镜像缺看 agent Pod events;补导镜像或自建 SA+RBAC
Webhook 403CSRF Crumb 校验Git 侧 webhook 加凭证,或 Jenkins 配 "Allow anonymous read"
升级后任务全丢PVC 没挂上/重建了 PVC灾难恢复 = 恢复 jenkins_home 备份
