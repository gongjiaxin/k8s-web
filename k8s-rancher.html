R1认识:Rancher 是什么、要多少资源

Rancher = 多集群 K8s 统一管理面板:网页上点选管多个集群的应用部署、RBAC、监控告警;本机所在集群装完后,下挂集群(agent)也由它纳管。它不替代 kubectl,是"驾驶舱"层。

项要求/说明
Chartrancher-stable/rancher(生产一律 stable 渠道,latest 别碰)
命名空间固定 cattle-system(组件全在这,名字不能改)
资源最低 2C4G,推荐 4C8G;装完还会拉起 fleet/rancher-webhook 等一串组件
前置依赖① 集群已有 ingress-nginx;② 一个能解析到集群的域名(必填,不支持裸 IP)
数据自身无状态(数据在 K8s 对象里),备份用 rancher-backup Operator
⚠️ 想清楚再装:Rancher 会往集群里装一堆 cattle-* 组件(fleet、webhook、impersonation 等 20+ 资源),卸载残留极难清干净;若只是要"一个 Dashboard 看板",K8s 自带 Dashboard 或 Lens 更轻。要多集群纳管/团队权限分发,Rancher 才值回票价。

R2版本锚定与离线准备

# 开发机:stable 渠道(★生产禁 latest)
helm repo add rancher-stable https://releases.rancher.com/server-charts/stable
helm search repo rancher-stable/rancher --versions | head -5
helm pull rancher-stable/rancher --version 2.9.3        # 得 rancher-2.9.3.tgz

# 镜像清单(rancher/rancher 主镜像 + 首启还会拉 fleet/webhook/system-agent 一串)
helm template rancher ./rancher-2.9.3.tgz -n cattle-system -f values-rancher.yaml \
  | grep -oP 'image:\s*\K\S+' | tr -d '"' | sort -u

# 离线四连(同 07 章套路):save → scp → ctr -n k8s.io import → 本地 tgz 安装
# ★注意:除 chart 模板里的镜像,Rancher 首次启动还会动态拉 fleet-*、rancher-webhook 等系统组件镜像,
#   离线环境导不全会表现为部分 Pod ImagePullBackOff,按报错逐个补导即可(k8s-monitor 07 章同款盲区)

R3values 配置全文

cat > values-rancher.yaml <<'EOF'
hostname: rancher.fftaicorp.com      # ★必填,不支持裸 IP
replicas: 1                          # 离线单点;HA 需 3 副本+外部 LB
ingress:
  tls:
    source: secret                   # ★自备证书(默认 source: rancher 为自签,浏览器告警)
bootstrapPassword: "Rancher-Init-2026"   # 首登引导密码(不设则随机,R4 有取法)
auditLog:
  level: 1                           # 审计元数据级
features: multi-cluster-management=true
EOF
⚠️ 证书是 Rancher 的命门:默认自签证书一年有效,过期后整个控制台 502/证书告警;source: secret 用公司统一证书(见 证书管理),secret 名固定 tls-rancher-ingress,续期流程见 R6。

R4安装与 bootstrap 密码

kubectl create namespace cattle-system
# 证书 secret(名字必须叫 tls-rancher-ingress,chart 引用写死)
kubectl -n cattle-system create secret tls tls-rancher-ingress \
  --cert=rancher.fftaicorp.com.pem --key=rancher.fftaicorp.com.key

helm install rancher ./rancher-2.9.3.tgz -n cattle-system -f values-rancher.yaml
kubectl -n cattle-system rollout status deploy/rancher       # waiting → successfully rolled out

# bootstrap 引导密码(values 没设时):
kubectl -n cattle-system get secret bootstrap-secret \
  -o jsonpath='{.data.bootstrapPassword}' | base64 -d; echo

# 首启拉起的系统组件(耐心等全绿;离线缺镜像时在这里暴露)
kubectl -n cattle-system get pods -w
kubectl -n cattle-fleet-system get pods 2>/dev/null
kubectl -n cattle-fleet-local-system get pods 2>/dev/null
💡 bootstrap 密码一次性:首次登录设置新 admin 密码后,bootstrap-secret 即失效 —— 和 GitLab 的 24h 初始密码同一设计哲学:临时凭证必须尽快消费掉。

R6日常运维命令速查

# ── 版本升级(stable 渠道内;大版本先看官方支持矩阵)──
helm upgrade rancher ./rancher-2.9.3.tgz -n cattle-system -f values-rancher.yaml
kubectl -n cattle-system rollout status deploy/rancher

# ── 证书续期(公司证书更换时三步)──
kubectl -n cattle-system create secret tls tls-rancher-ingress \
  --cert=new.pem --key=new.key --dry-run=client -o yaml | kubectl apply -f -
kubectl -n cattle-system rollout restart deploy/rancher      # 让 ingress 重读

# ── 备份:rancher-backup Operator(独立 chart,按 CR 定期备份到 S3/PVC)──
helm install rancher-backup rancher-backup/rancher-backup -n cattle-resources-system --create-namespace

# ── 纳管新集群 ──
#   UI: Add Cluster → Import → 得到一条 kubectl apply 注册命令 → 去目标集群执行 → Approve
kubectl -n cattle-system get pods -o wide | grep -E "rancher-|webhook"

# ── 观察系统组件健康 ──
kubectl get pods -A | grep -E "cattle|rancher|fleet" | grep -v Running

R7排障速查

症状真因处置
控制台整体 502/证书告警自签证书一年到期换 tls-rancher-ingress secret(R6 续期三步)
kubectl apply 全被拒(webhook)rancher-webhook Pod 异常看 webhook Pod 日志;极端时临时删 validatingwebhookconfiguration(恢复后自动重建)
下挂集群 agent 不健康目标集群连不上 rancher 域名目标集群内 curl rancher 域名;cattle-cluster-agent 日志
fleet/webhook Pod ImagePullBackOff离线漏导系统组件镜像按 events 镜像名逐个 ctr 补导(07 章同款盲区)
升级卡 Rollingreplicas>1 无 LB / 前一版本未就绪单点集群固定 replicas: 1
