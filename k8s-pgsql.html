P1认识与选型:单机 or 1主1备

Bitnami PostgreSQL Chart 同样一个开关切形态(replication.enabled):

形态架构自动切换适用
★ 单机(默认,replication.enabled=false)1 实例 + PVC—(Pod 挂了原样拉起,数据不丢)绝大多数内网应用;PVC + 定期 pg_dump 已够
1主1备(replication.enabled=true,本文演示)primary + read 副本,流复制无(主挂需人工提升副本)读写分离 + 热备
Patroni/CloudNativePG Operator3 节点自动选主有要求 RPO≈0 的核心库
💡 选型口诀:"重要数据 + 能接受分钟级人工恢复" = 单机 + 好备份,比"半吊子主从"更稳 —— 主从不自动切换的形态,故障时反而多一步"确认该不该提升副本"。要全自动高可用请直接上 CloudNativePG,别在中间形态纠结。

P2版本锚定与离线准备(★bitnamilegacy 坑)

# 开发机:
helm repo add bitnami https://charts.bitnami.com/bitnami && helm repo update
helm search repo bitnami/postgresql --versions | grep -E 'CHART|16\.' | head -6
# 选 APP VERSION = 16.x(PG 大版本升级必须 dump/restore,不能 chart 直接跳 —— 锁死 16)
helm pull bitnami/postgresql --version 16.4.5           # 得 postgresql-16.4.5.tgz

# ★Bitnami 2025-08 迁移坑(同 MySQL/Redis 篇):
#   docker.io/bitnami/* 免费镜像已清空归档到 bitnamilegacy —— image.repository 必须改!
curl -s 'https://hub.docker.com/v2/repositories/bitnamilegacy/postgresql/tags/?name=16&page_size=10' \
  | grep -o '"name":"[^"]*"' | head -3

# 镜像清单 + 离线四连:
helm template pg ./postgresql-16.4.5.tgz -n pgsql -f values-pgsql.yaml \
  | grep -oP 'image:\s*\K\S+' | tr -d '"' | sort -u
docker save -o pgsql-images.tar bitnamilegacy/postgresql:16.4-r0 ...
scp postgresql-16.4.5.tgz pgsql-images.tar root@10.18.51.120:/root/k8s-install/pca/
ctr -n k8s.io images import pgsql-images.tar
helm install pg ./postgresql-16.4.5.tgz -n pgsql --create-namespace -f values-pgsql.yaml
⚠️ 大版本红线:PostgreSQL 16 → 17 属于不兼容升级(内部数据格式变化),chart 直接升 = 起不来。升级路径 = pg_dumpall → 新版本恢复(见 P6)。所以选型时就锁死团队应用支持的版本。

P3values 配置全文(单机 + 可选 1主1备)

cat > values-pgsql.yaml <<'EOF'
auth:
  username: app
  password: "Pg-Proda-2026"          # 生产走 existingSecret
  database: appdb
primary:
  persistence:
    enabled: true
    storageClass: longhorn           # ★本集群存储类
    size: 20Gi
  resources:
    requests: {cpu: 250m, memory: 256Mi}
    limits:   {memory: 2Gi}
  extendedConfiguration: |
    max_connections = 200            # 按应用连接池规划
# ---- 只读热备(默认注释掉 = 纯单机;要 1主1备再放开)----
# replication:
#   enabled: true
#   singlePrimary: true
# readReplicas:
#   replicaCount: 1
#   persistence:
#     enabled: true
#     storageClass: longhorn
#     size: 20Gi
image:
  repository: bitnamilegacy/postgresql   # ★迁移坑
  tag: 16.4.0-debian-12-r0              # 以 P2 查到的精确 tag 为准
metrics:
  enabled: true                          # exporter 接 07 章监控
EOF
💡 密码变更的唯一正路:装完后想改密码,不能只改 values 里的 auth.password —— chart 只在首次安装生成 Secret,后续 upgrade 不会回写数据库内密码(见 P7 排障)。改密要 ALTER USER + 同步 Secret 两步走。

P4安装与验证(psql / 复制状态)

kubectl -n pgsql get pods -w                # pg-postgresql-0(+ 开复制时再加 pg-read-0)

# 连通 + 建库验证
kubectl -n pgsql exec pg-postgresql-0 -- psql -U app -d appdb -c '\l'
kubectl -n pgsql exec pg-postgresql-0 -- pg_isready -U app
kubectl -n pgsql exec pg-postgresql-0 -- psql -U app -d appdb -c 'CREATE TABLE t1(id int); INSERT INTO t1 VALUES (1); SELECT * FROM t1;'

# 开了 1主1备时:主上查复制(一行 streaming = 打通)
kubectl -n pgsql exec pg-postgresql-0 -- psql -U postgres \
  -c "SELECT application_name, state, sync_state FROM pg_stat_replication;"

# 应用连接串(集群内)
kubectl -n pgsql get svc
#   pg-postgresql:5432(读写主)/ pg-postgresql-read:5432(开复制后的只读入口)
# 集群内应用:postgresql://app:密码@pg-postgresql.pgsql.svc:5432/appdb

P5日常运维命令速查

# ── 应用上线标配:建用户授权 ──
kubectl -n pgsql exec -it pg-postgresql-0 -- psql -U app -d appdb \
  -c "CREATE USER svc_app WITH PASSWORD 'S3cret!';"
kubectl -n pgsql exec -it pg-postgresql-0 -- psql -U app -d appdb \
  -c "GRANT ALL PRIVILEGES ON DATABASE appdb TO svc_app;"

# ── 日常体检 ──
kubectl -n pgsql exec pg-postgresql-0 -- psql -U app -d appdb -c '\dt'
kubectl -n pgsql exec pg-postgresql-0 -- psql -U app -d appdb \
  -c "SELECT pg_size_pretty(pg_database_size('appdb'));"
kubectl -n pgsql exec pg-postgresql-0 -- psql -U app -d appdb \
  -c "SELECT count(*), state FROM pg_stat_activity GROUP BY state;"    # 活动连接

# ── 在线扩容 PVC(longhorn 支持)──
kubectl -n pgsql patch pvc data-pg-postgresql-0 \
  --patch '{"spec":{"resources":{"requests":{"storage":"50Gi"}}}}'

# ── 滚动重启 ──
kubectl -n pgsql rollout restart sts pg-postgresql

P6备份与恢复(pg_dump 全流程)

# ── 单库逻辑备份(应用数据)──
kubectl -n pgsql exec pg-postgresql-0 -- pg_dump -U app appdb > appdb_$(date +%F).sql
# ── 全实例(含角色/库定义 —— 大版本升级也靠它)──
kubectl -n pgsql exec pg-postgresql-0 -- pg_dumpall -U postgres > all_$(date +%F).sql

# ── 恢复(单库)──
kubectl -n pgsql exec -i pg-postgresql-0 -- psql -U app -d appdb < appdb_2026-11-24.sql

# ── 定时备份:CronJob 思路(每日 2 点 dump 到 PVC → kubectl cp / S3 取回)──
#  kubectl create cronjob pg-bak --schedule="0 18 * * *" --image=bitnamilegacy/postgresql:16.4 -- pg_dump …

# ── 大版本升级正路(16 → 17):新 namespace 装 17 → pg_dumpall 导入 → 切连接串 ──
💡 备份验证清单:每月挑一份备份在临时 namespace 恢复一遍(helm install pg-restore … → psql < dump)——没验证过的备份等于没有备份;并把 PVC 用量、备份成功率接进 7.13 的钉钉告警。
