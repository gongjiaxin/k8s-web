G1认识与选型:装哪个 GitLab

K8s 里跑 GitLab 有两条路,先对号入座:

方案形态资源适用
★ 官方 gitlab/gitlab Chart(本文)Omnibus 全家桶:Rails + Gitaly + Registry + 内置 PG/Redis/MinIO,一条 Helm 命令全拉起最低 4C8G,推荐 8C16G要完整 GitLab(代码+MR+CI+镜像仓库)
轻量自拼Gitea / 仅 gitlab-runner 对接外部 GitLab0.5C512M 起只要代码托管,或公司已有中心 GitLab

官方 Chart 装完会拉起这些组件(kubectl -n gitlab get pods 会看到的):

Pod 前缀角色说明
migrations数据库迁移 Job每次升级都先跑它,失败则整体卡住
webserviceWeb 主进程(Puma)吃内存大户,UI/API 都走它
sidekiq后台任务邮件/CI 调度/Webhook
gitalyGit 数据存储★ 仓库数据在这,必须持久化
gitlab-shellSSH/git 协议入口git@ 克隆走它
registry容器镜像仓库CI 构建镜像可推这里(也可推 Harbor)
postgresql / redis / minio内置依赖生产建议外置(见 G3 注释)
⚠️ 资源红线:内存 < 8G 的集群别上全家桶 —— webservice/sidekiq 会反复 OOMKilled,装之前先 kubectl top nodes 确认可用余量;小集群请走轻量自拼方案。

G2版本锚定与离线准备

# 开发机(能上外网):加仓库、锁版本、下 tgz —— ★离线集群别用 helm install 直连远程
helm repo add gitlab https://charts.gitlab.com/ && helm repo update
helm search repo gitlab/gitlab --versions | head -6
# 版本对照(装前查官方 upgrade path):chart 8.x ↔ GitLab 16.x;7.x ↔ 15.x —— 跟存量数据对齐,别追最新
helm pull gitlab/gitlab --version 8.9.5                 # 得 gitlab-8.9.5.tgz

# 提取镜像清单(★先写好 values 再 template,清单才准)
helm template gitlab ./gitlab-8.9.5.tgz -n gitlab -f values-gitlab.yaml \
  | grep -oP 'image:\s*\K\S+' | tr -d '"' | sort -u
# 全家桶 ≈ 10+ 个镜像(rancher/webservice/sidekiq/gitaly/shell/registry/pg/redis/minio…),总计 ~3GB+

# 离线四连(同 k8s-monitor.html 07 章实测套路):
docker save -o gitlab-images.tar 镜像1 镜像2 ...        # 开发机打包
scp gitlab-8.9.5.tgz gitlab-images.tar root@10.18.51.120:/root/k8s-install/pca/
ctr -n k8s.io images import gitlab-images.tar           # master 导入(多节点记得每台都导或走 DaemonSet)
helm install gitlab ./gitlab-8.9.5.tgz -n gitlab -f values-gitlab.yaml   # 本地 tgz 安装
💡 为什么 save 包这么大:GitLab Chart 是"全家桶"形态,内置 PostgreSQL/Redis/MinIO 一并打包;kubectl top nodes 先确认每节点余量,内存紧张的节点会被调度器自动避开(配合 resources 设置)。

G3values 配置全文(离线集群精简版)

cat > values-gitlab.yaml <<'EOF'
global:
  edition: ce                          # 社区版
  hosts:
    domain: fftaicorp.com              # 自动生成 gitlab.fftaicorp.com / registry. 前缀域名
    https: true
  ingress:
    configureCertmanager: false        # ★离线禁 cert-manager 自动签发
    class: nginx                       # ★复用集群已有 ingress-nginx
    tls:
      secretName: gitlab-tls           # 自备证书 secret(见 G4)
certmanager:
  install: false
nginx-ingress:
  enabled: false                       # 不装 chart 自带 ingress 控制器
prometheus:
  install: false                       # 复用 07 章 kube-prometheus-stack
gitlab-runner:
  install: false                       # 主体先稳,runner 单独规划
gitlab:
  gitaly:
    persistence:
      size: 50Gi
      storageClass: longhorn           # ★Git 仓库数据全在 gitaly
  toolbox:
    backups:
      objectStorage:
        backend: local                 # 备份先落 PVC(异机取回见 G6)
postgresql:
  primary:
    persistence:
      size: 20Gi
      storageClass: longhorn
redis:
  master:
    persistence:
      size: 10Gi
      storageClass: longhorn
minio:
  persistence:
    size: 20Gi
    storageClass: longhorn
EOF
⚠️ 两个生产提醒:① 内置 PG/Redis/MinIO 只适合中小规模,数据量大或要求独立升级时外置(global.psql / global.redis 指向外部实例),内网已有 MySQL/外部 PG 的可以直接复用;② storageClass 按本集群实际填(new-k8s 为 longhorn),填错 PVC 永远 Pending。

G4安装与初始化(root 密码)

kubectl create namespace gitlab
# 域名证书(参考 k8s-cert.html;泛域名证书一张可覆盖 gitlab./registry./minio. 全套)
kubectl -n gitlab create secret tls gitlab-tls \
  --cert=_.fftaicorp.com.pem --key=_.fftaicorp.com.key

helm install gitlab ./gitlab-8.9.5.tgz -n gitlab -f values-gitlab.yaml
kubectl -n gitlab get pods -w
# 起来顺序:migrations(Job)→ postgresql/redis/minio → sidekiq → webservice(最慢,数分钟)

# ★初始 root 密码 —— 装完立刻取!(secret 24 小时后自动删除)
kubectl -n gitlab get secret gitlab-gitlab-initial-root-password \
  -o jsonpath='{.data.password}' | base64 -d; echo

# 健康检查(webservice 就绪才算好)
kubectl -n gitlab get ingress
curl -k https://gitlab.fftaicorp.com/-/health     # 经反代后 GitLab OK
⚠️ 24 小时红线:gitlab-gitlab-initial-root-password 这个 secret 首次成功登录(或 24h)后自动删除 —— 装完第一时间用 root 登录改密,别等第二天。

G5访问入口与首登加固

本环境套路 = 外层 NGINX 反代 → ingress-nginx NodePort → GitLab Ingress(同 new-k8s/Harbor 篇):

# /etc/nginx/conf.d/gitlab.fftaicorp.com.conf(办公网入口机)
upstream gitlab_fke { server 10.18.51.120:32588; }     # ingress-nginx 的 NodePort
server {
    listen 443 ssl;
    server_name gitlab.fftaicorp.com;
    ssl_certificate     /etc/nginx/ssl/_.fftaicorp.com.pem;
    ssl_certificate_key /etc/nginx/ssl/_.fftaicorp.com.key;
    client_max_body_size 0;                 # ★大仓库 push 不限
    location / {
        proxy_pass http://gitlab_fke;
        proxy_set_header Host $host;        # ★灵魂行
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 300s;
    }
}
  • 浏览器开 https://gitlab.fftaicorp.com → root + 初始密码登录 → 立即改密。
  • 首登必做:关闭公开注册 —— Admin Area → Settings → General → Sign-up restrictions → 取消 Sign-up enabled(否则内网任何人可自助注册账号)。

G6日常运维命令速查

# ── 升级(同大版本内;跨大版本查官方 upgrade path 逐级走,先备份!)──
helm upgrade gitlab ./gitlab-8.9.5.tgz -n gitlab -f values-gitlab.yaml
kubectl -n gitlab get jobs | grep migration        # 每次升级先跑 migrations Job,成功才继续

# ── 组件状态/日志 ──
kubectl -n gitlab get pods -o wide
kubectl -n gitlab logs deploy/gitlab-webservice-default --tail=100
kubectl -n gitlab exec deploy/gitlab-toolbox -- gitlab-ctl status

# ── 备份(仓库+DB → PVC 内 /var/opt/gitlab/backups)──
kubectl -n gitlab exec deploy/gitlab-toolbox -- backup-utility
# 最新备份文件异机取回:
kubectl -n gitlab cp $(kubectl -n gitlab get pod -l app=toolbox -o name | cut -d/ -f2):/var/opt/gitlab/backups ./gitlab-bak -c toolbox
# ★secrets 必须单独备(CI 变量/2FA 的解密钥匙,不在 backup-utility 里!)
kubectl -n gitlab get secret gitlab-gitlab-rails-secret -o yaml > gitlab-rails-secret.yaml

# ── root 密码重置(初始 secret 过期/遗忘)──
kubectl -n gitlab exec -it deploy/gitlab-toolbox -- gitlab-rake "gitlab:password:reset[root]"

# ── 资源观察(谁在吃内存)──
kubectl top pods -n gitlab | sort -k3 -h | tail -5
