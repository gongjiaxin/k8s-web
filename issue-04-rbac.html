04 🔑 权限问题 —— Permission denied / RBAC 容器内权限、节点 SELinux、kubectl 认证授权,三类问题分开治

① 挂载目录没写权限(数据库类应用第一名坑)

# 现象:Pod 反复 CrashLoopBackOff,logs 里是经典的 permission denied
kubectl logs mysql-0 -n prod
mkdir: cannot create directory '/var/lib/mysql': Permission denied

# 解决:Pod securityContext 加 fsGroup(让 kubelet 把卷 chown 给该组)
#      fsGroup 的值 = 镜像内运行业务的系统用户组 id(mysql 官方镜像为 999)
spec:
  securityContext:
    fsGroup: 999
    runAsUser: 999
    runAsGroup: 999

② SELinux 拦截(CentOS / RHEL 常见)

# 快速判断:临时关闭后能写了,就是 SELinux 的锅
setenforce 0          # 临时 Permissive(重启失效)

# 正确做法(别长期关闭):给目录打容器标签
chcon -Rt svirt_sandbox_file_t /data/nfs/mysql
# 永久生效用 semanage fcontext -a -t svirt_sandbox_file_t "/data/nfs/mysql(/.*)?" && restorecon -Rv /data/nfs/mysql

③ RBAC / 认证类报错

报错根因解决方案
Forbidden: User "system:anonymous" cannot get ...kubeconfig 没带凭证 / 权限未绑定检查 KUBECONFIG;给 SA 绑 Role/ClusterRole
x509: certificate has expired集群证书到期(常伴随节点时间不准)ntpdate 校时;kubeadm certs renew all + 重启控制面
You must be logged in to the server (Unauthorized)client 证书/ token 失效重新分发 admin.conf 或重新签发用户证书
# 权限自检两连:我是谁 / 我能不能
kubectl config current-context
kubectl auth can-i get pods -n prod          # 回答 yes/no,一目了然
kubectl auth can-i '*' '*' --as=system:serviceaccount:prod:deploy-sa

# 看证书还剩多久
kubeadm certs check-expiration
💡 定位口诀:容器内报 Permission denied → 先 fsGroup;节点上手工写也失败 → 查 SELinux/目录属主;kubectl 报 Forbidden/Unauthorized → 查 RBAC/证书。三类权限别混。
