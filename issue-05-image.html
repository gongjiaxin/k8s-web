05 📦 拉不下镜像 —— ImagePullBackOff 五类根因对照 + 四套方案:国内加速 / 离线导入 / 私有仓库凭证,总有一款救活你

典型现象与四类根因

kubectl get pods -n web
nginx-6b7f5d8c-x9k2p   0/1   ImagePullBackOff   0   3m

kubectl describe pod nginx-6b7f5d8c-x9k2p -n web | grep -A3 "Failed to pull"
  Failed to pull image "nginx:1.27": failed to pull and unpack ... i/o timeout
Events 里的报错根因跳转方案
manifest unknown / not found镜像名或 Tag 写错方案 A
i/o timeout / no route to host国内网络拉不到 Docker Hub方案 B(加速器)
toomanyrequests / rate limitedDocker Hub 限流方案 B / C
unauthorized: authentication required私有仓库没带凭证方案 D(imagePullSecrets)
exec format error架构不匹配(x86 机器拉了 arm64 镜像)换 nginx:1.27-amd64 类带架构 Tag

方案 A:先确认镜像真的存在

# 在任意节点上手工拉一次,报 not found 就是名字/Tag 写错
crictl pull nginx:1.27

方案 B:containerd 配置国内加速(一劳永逸)

# 1. /etc/containerd/config.toml 启用 certs.d 目录(v2 推荐方式)
[plugins."io.containerd.grpc.v1.cri".registry]
  config_path = "/etc/containerd/certs.d"

# 2. 给 docker.io 配加速源:/etc/containerd/certs.d/docker.io/hosts.toml
server = "https://docker.io"
[host."https://docker.m.daocloud.io"]
  capabilities = ["pull", "resolve"]
#   ★ 加速器对某些仓库(如 bitnamilegacy)可能挂起/不回源 → pull 卡住不动:
#     先 rm hosts.toml 恢复直连(机器 curl 通 docker.io 就直连可拉);
#     直连也不行再换源:docker.1ms.run / dockerproxy.net 等,改 [host."..."] 后重启 containerd

# 3. 重启生效(改了配置不重启 = 白改)
systemctl restart containerd
crictl pull nginx:1.27        # 现在应该秒拉

# 4. sandbox/pause 镜像也超时的话,init 第一步就卡死 —— 顺手改同文件里
#    sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.10"

方案 C:离线导入(内网/保密环境终极方案)

# 有网机器上导出,拷进内网节点导入(注意必须是 k8s.io 命名空间)
ctr -n k8s.io images import nginx-1.27.tar
crictl images | grep nginx   # 能看到即成功,Pod 会自动重试拉起

方案 D:私有仓库认证(Harbor 等)

# 1. 建拉取凭证(用户名里 $ 记得转义,Robot 账号常见)
kubectl create secret docker-registry regcred -n web \
  --docker-server=harbor.qingfeng.local \
  --docker-username='robot$ci' \
  --docker-password='Harbor12345'

# 2. Pod/Deployment spec 里引用
spec:
  imagePullSecrets:
  - name: regcred
💡 私仓完整实践(Robot 账号、CI 推送、admission webhook 排障)见 Harbor 安装与使用;修改镜像后不想等退避重试,kubectl delete pod xxx 重建最快。
