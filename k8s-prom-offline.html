01线上安装方式与版本锚点(fke,怎么查的)

离线安装第一步不是下载,而是确认线上装的是什么、什么版本——新环境与线上对齐,经验才能迁移。两条命令搞定:

# 是不是 Helm 装的?release 叫什么?在哪个 ns?
sudo helm list -A | grep -iE "prometheus|monitoring|kube-prom"

# 本机配置过哪些仓库源
sudo helm repo list

线上真实输出(2025-11-23 于 fke-m1 执行):

fourier@fke-m1:~$ sudo helm list -A | grep -iE "prometheus|monitoring|kube-prom"
prometheus                  fke-monitor         6        2025-09-22 10:10:33.421976192 +0800 CST    deployed    kube-prometheus-stack-48.2.0    v0.66.0

fourier@fke-m1:~$ sudo helm repo list
Error: no repositories to show
字段值含义
release 名prometheus新环境保持同名,命令习惯一致
namespacefke-monitor监控栈专用 ns
revision6已升级过 6 次,最新一次 2025-09-22
chartkube-prometheus-stack-48.2.0★ 离线下载就锁这个版本
app versionv0.66.0Prometheus Operator 版本
repo list 为空怎么解读:说明当初安装那台机器没配(或后来清掉了)helm 仓库源,不影响判断——release 信息本身就证明了是 Helm 装的。新环境照常 helm repo add 即可。

02开发机下载:Chart 包 + 镜像清单(★ 动态提取法)

在能上外网的开发机(本次为 qingfeng,工作目录 ~/k8s-install/pca)上完成三件事:下 Chart、列镜像、拉镜像。

2.1 下载 Chart 包(1 个 tgz 含全部子依赖)

helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# 锁定线上同版本 → 得到 kube-prometheus-stack-48.2.0.tgz
helm pull prometheus-community/kube-prometheus-stack --version 48.2.0

# 验证:charts/ 子依赖应已内置 grafana / kube-state-metrics / prometheus-node-exporter
tar -tzf kube-prometheus-stack-48.2.0.tgz | head -20
自包含:helm pull 下来的 tgz 已把 3 个子 chart 打包在内,新集群离线安装时直接用这一个文件,无需再联网拉依赖。实测仅 468K。

2.2 镜像清单:不要手写,用渲染提取(★ 本页最值钱的方法)

# 用本地 chart 渲染出真实镜像清单 → images.txt
helm template prometheus kube-prometheus-stack-48.2.0.tgz -n fke-monitor \
  | grep 'image:' | sed 's/.*image: *//' | tr -d '"' | sort -u > images.txt

cat images.txt
为什么必须动态提取:本页实测就踩到了——chart 48.2.0 实际渲染出的 tag 与网上资料差异不小(grafana 是 10.0.2、prometheus 是 v2.45.0、kube-state-metrics 是 v2.9.2)。手抄清单必漏必错,helm template 渲染是唯一事实源;改了 values 就重跑一遍。

04传输:scp for 循环分发 6 节点

new-k8s 拓扑:m1(master,本机)+ 10.18.51.121~125(5 worker)。镜像 tar 要人手一份:

# 在 new-k8s-fke-m1 上:循环 scp 到 121~125(master 本机不用传给自己)
for i in `seq 121 125`; do echo 10.18.51.$i; scp /tmp/prom-images.tar root@10.18.51.$i:/tmp/; done

05镜像导入:ctr 全节点导入 + crictl 验证

5.1 导入(先本机,再循环)

# ① master 本机(文件就在本机 /tmp,不用 ssh)
ctr -n k8s.io images import /tmp/prom-images.tar

# ② 121~125 循环导入(与 scp 同款写法)
for i in `seq 121 125`; do echo 10.18.51.$i; ssh root@10.18.51.$i "ctr -n k8s.io images import /tmp/prom-images.tar"; done

两个必踩坑:
1) -n k8s.io 不能省——不带就导进 default ns,kubelet 看不到,照样 ImagePullBackOff;
2) 每台都要导——node-exporter 是 DaemonSet(6 节点每台一个),Prometheus/Grafana 调度到哪台不受控。

06Helm 离线安装(values 裁剪 + kubeVersion 大坑)

6.1 先过兼容性检查(kubeVersion 大坑)

kubectl version
chart 48.2.0 声明了 kubeVersion 上限(2023 年的 chart,当时上限 <1.28)。若 new-k8s 版本较新,helm install 会直接报 Chart requires kubeVersion ... which is incompatible。解法(解开包删掉限制再装): 
tar -xzf kube-prometheus-stack-48.2.0.tgz
# 编辑 kube-prometheus-stack/Chart.yaml,删除或放宽 kubeVersion: 一行
helm install prometheus ./kube-prometheus-stack -n fke-monitor --create-namespace

6.2 values 裁剪(离线/最小可用)

# 检查新集群 StorageClass(Prometheus/Alertmanager/Grafana 持久化要用)
kubectl get sc
# prom-values-offline.yaml(按需裁剪,未列出的用 chart 默认)
grafana:
  adminPassword: "admin123"          # 改掉默认 admin/admin
  defaultDashboardsEnabled: true

prometheus:
  prometheusSpec:
    retention: 7d                     # 与线上策略对齐
    storageSpec:
      volumeClaimTemplate:
        spec:
          storageClassName: <新集群的SC名>   # kubectl get sc 查到什么填什么
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 50Gi

alertmanager:
  alertmanagerSpec:
    storage:
      volumeClaimTemplate:
        spec:
          storageClassName: <新集群的SC名>
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 5Gi

6.3 先演练再正式装

# dry-run:本地渲染验证,不落集群(能提前暴露 kubeVersion / 模板错误)
helm install prometheus ./kube-prometheus-stack-48.2.0.tgz \
  -n fke-monitor --create-namespace \
  -f prom-values-offline.yaml --dry-run > dry-run.yaml

# 正式安装(本地 tgz,全程无外网)
helm install prometheus ./kube-prometheus-stack-48.2.0.tgz \
  -n fke-monitor --create-namespace \
  -f prom-values-offline.yaml

helm list -n fke-monitor
镜像已就位就不怕:chart 默认 imagePullPolicy 为 IfNotPresent,ctr 导入后 kubelet 直接本地命中,不会去外网拉镜像。

08维护手册(巡检 / 离线升级 / 卸载 / 报错速查)

8.1 日常巡检

kubectl get pods -n fke-monitor                       # Pod 健康
kubectl top pods -n fke-monitor                       # 资源
kubectl get pvc -n fke-monitor                        # 存储绑定
crictl images | grep -cE 'prometheus|grafana'          # 本机镜像还在
helm list -n fke-monitor                              # release 状态

8.2 离线升级(4 步循环)

# ① 开发机:拉新版 chart + 动态提取新镜像并 save
helm pull prometheus-community/kube-prometheus-stack --version <新版本>
helm template ... | grep 'image:' | ... > images-new.txt
docker save -o prom-images-new.tar $(tr '\n' ' ' < images-new.txt)
# ② scp 分发 + ctr 导入(本文 04/05 章同款 for 循环)
# ③ master:helm upgrade(本地 tgz)
helm upgrade prometheus ./kube-prometheus-stack-<新版本>.tgz -n fke-monitor -f prom-values-offline.yaml
# ④ 回退
helm rollback prometheus <revision> -n fke-monitor

8.3 卸载

helm uninstall prometheus -n fke-monitor
# PVC 不会随 release 删除,确认不要数据了再手动清:
kubectl delete pvc --all -n fke-monitor

8.4 报错速查

症状原因解法
ImagePullBackOff该节点漏导镜像 / 导入时没带 -n k8s.io补 ctr -n k8s.io images import,用 05 章 for 循环验证计数
Pending(PVC 绑不上)storageClassName 在新集群不存在kubectl get sc 核对,改 values 里的 SC 名
helm install 直接报 kubeVersion 不兼容chart 48.2.0 声明的 K8s 版本上限06.1:解包删 Chart.yaml 的 kubeVersion 行再装
node-exporter 某台 CrashLoop该节点镜像/权限差异kubectl describe pod 看事件,crictl images 核对该节点
