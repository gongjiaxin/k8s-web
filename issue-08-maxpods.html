08 🔢 节点能跑多少 Pod 不够使用 —— maxPods 查询修改与调整 110 是默认值不是真实值:两条命令查上限与用量,改 kubelet 在线调整

查询命令(两条就够)

# 1. 最多能跑几个:读节点 status.allocatable.pods(kubelet 上报的可分配上限)
kubectl get node qingfeng -o jsonpath='{.status.allocatable.pods}'; echo
110

# 2. 已经用了多少:describe 的 Allocated resources 段,盯 pods 那一行
kubectl describe node qingfeng | grep -A8 'Allocated resources'
  Resource           Requests      Limits
  cpu                850m (21%)    300m (7%)
  memory             690Mi (9%)    512Mi (7%)
  ephemeral-storage  0 (0%)        0 (0%)
  pods               7 (6%)        0 (0%)      ← 已分配 7 个 / 上限 110

# 附加:所有节点容量一览表
kubectl get nodes -o custom-columns='NODE:.metadata.name,MAX-PODS:.status.allocatable.pods'
NODE       MAX-PODS
qingfeng   110

# 多节点集群:全部节点的 Pod 容量"总和"(jsonpath 逐行取出再 awk 累加)
kubectl get nodes -o jsonpath='{range .items[*]}{.status.allocatable.pods}{"\n"}{end}' \
  | awk '{s+=$1} END{print "集群 Pod 总容量:", s}'

# 明细 + 合计一起看(表格末尾追加 TOTAL 行)
kubectl get nodes -o custom-columns='NODE:.metadata.name,MAX-PODS:.status.allocatable.pods' \
  | awk 'NR>1{print; s+=$2} END{print "--------"; printf "TOTAL\t%d\n", s}'

# 对比"已经用了多少":集群当前 Pod 总数 / 只数 Running
kubectl get pods -A --no-headers | wc -l
kubectl get pods -A --field-selector=status.phase=Running --no-headers | wc -l

110 是怎么评估出来的?

  • 不是算出来的,是默认值:110 来自 kubelet 参数 --max-pods(即 KubeletConfiguration 的 maxPods: 110),kubelet 启动时把它写进 status.capacity.pods 并上报 apiserver —— 这是社区经验值,兼顾每个 Pod 的进程/内存开销。
  • 默认值不一定真是 110:发行版/云厂商常会定制(实测 FKE 集群节点为 100) —— 所以别硬编码 110,以 allocatable.pods 查询结果为准;"集群总容量" = 各节点 allocatable.pods 逐个相加(见上方 jsonpath+awk 命令)。
  • 真正还能不能调度,是调度器综合判断:min(maxPods, 剩余 CPU requests, 剩余内存 requests, CNI 剩余 IP)。所以即便 pods 显示 (6%) 很空闲,CPU 100% 照样 Pending(见附 · 状态速查表)。
  • 隐性上限还有三个:CNI 每节点 Pod CIDR(Flannel 默认 /24 = 254 个 IP)、节点级 PID 上限(每 Pod 至少 1 个容器进程)、云厂商 CNI(如阿里云 Terway / AWS VPC CNI 按 ENI×辅助 IP 数限制,此时 maxPods 由厂商参数决定)。

后期可以修改吗 —— 可以,只改 kubelet,不用动集群

# 1. 先确认当前生效值(节点上的 kubelet 配置)
grep maxPods /var/lib/kubelet/config.yaml
maxPods: 110

# 2. 改成目标值(如 200)
sed -i 's/^maxPods:.*/maxPods: 200/' /var/lib/kubelet/config.yaml

# 3. 重启 kubelet 生效(节点上执行,秒级,不影响已运行 Pod)
systemctl restart kubelet

# 4. 验证:上报的 allocatable.pods 已变成新值
kubectl get node qingfeng -o jsonpath='{.status.allocatable.pods}'; echo
200
⚠️ 调大之前先确认:maxPods 只解"数量名额",不解资源 —— CPU/内存(02 磁盘同理)、CNI IP 池、PID 上限真的撑得住才能调;云托管集群(ACK/EKS/GKE)的默认值和改法由厂商参数/CNI 决定,别直接改托管节点。调小则要谨慎:低于当前已运行 Pod 数会导致节点被判超卖。

易混点:node 和 namespace 是两种东西,别搞混

kubectl get node qingfeng 查的是节点(一台真实的机器,本集群单节点就叫 qingfeng) —— maxPods 是节点属性,所以要 get node;而 namespace 是集群里的逻辑分区(default / kube-system / harbor ...),只负责把资源分组隔离,和节点没有包含关系。

node 节点namespace 命名空间
是什么一台跑容器的机器(kubelet 所在)集群内的逻辑分组/虚拟小集群
典型名字qingfeng、worker-01default、kube-system、harbor、prod
查看命令kubectl get nodeskubectl get ns
Pod 数量上限maxPods(kubelet,默认 110)ResourceQuota 的 pods: N(不配则不限)
# 查看某个命名空间
kubectl get ns                       # 列出全部命名空间
kubectl get ns harbor -o wide        # 看某个 ns 的状态
kubectl describe ns harbor           # 详情:标签、资源配额(Quota)、状态

# "看一个 ns 里的东西"(最常见诉求,用 -n 指定)
kubectl get pods -n harbor           # 该 ns 的 Pod
kubectl get all -n harbor            # Pod/Svc/Deploy 一次全看
kubectl get pods -A                  # 想全看就去掉 -n 加 -A

# ns 级别的 Pod 数上限 = ResourceQuota(不建就没有限制)
kubectl get resourcequota -n harbor
# 给 harbor ns 限制最多 50 个 Pod:
kubectl create quota pod-limit -n harbor --hard=pods=50
💡 一句话分清:node 管"在哪台机器上跑、最多跑几个"(maxPods);namespace 管"资源属于哪个组、组里能用多少"(ResourceQuota) —— 查前者 get node,查后者 get ns,查"某个组里的资源"要加 -n。
