02 💾 磁盘问题 —— 磁盘满 / DiskPressure 驱逐 节点打上 DiskPressure、大批 Pod Evicted:三大户定位 → 按安全顺序清理 → 阈值兜底

典型现象

# 节点被打了磁盘压力标签
kubectl describe node qingfeng | grep -A2 DiskPressure
  DiskPressure   True   KubeletHasDiskPressure   kubelet has disk pressure

# 大批 Pod 被驱逐(Evicted)
kubectl get pods -A | grep -i evicted
harbor   harbor-core-5d7c9f8b-x2k9p   Evicted   0   23h

# 应用写文件直接报错(数据库最常见,见 06)
IOError: [Errno 28] No space left on device

排查:先找到磁盘被谁吃掉

# 1. 总览:运行时与 kubelet 所在分区
df -h /var/lib/containerd /var/lib/kubelet

# 2. 三大户逐一定位(镜像层 / 容器日志 / journald)
du -h --max-depth=1 /var/lib/containerd | sort -rh | head
du -h --max-depth=1 /var/log/pods     | sort -rh | head   # 容器 stdout 日志
journalctl --disk-usage

清理(按安全顺序执行)

# 1. 删"没有任何 Pod 在用"的镜像(最安全、见效最快)
crictl rmi --prune

# 2. 收缩 journald 系统日志,只保留 3 天
journalctl --vacuum-time=3d

# 3. 清理已被驱逐/失败的 Pod 残留
kubectl delete pods -A --field-selector=status.phase=Failed

# 4. 长效:限制单容器日志体积(/var/lib/kubelet/config.yaml)
containerLogMaxSize: 50Mi
containerLogMaxFiles: 3
# 改完 systemctl restart kubelet

兜底:临时下调驱逐阈值(只救急,清完就改回)

# /var/lib/kubelet/config.yaml
evictionHard:
  nodefs.available: "5%"
  imagefs.available: "5%"
# systemctl restart kubelet 后 DiskPressure 会自动恢复为 False
⚠️ 千万别:直接 rm -rf /var/lib/containerd/io.containerd.* 里的目录 —— 会把正在用的镜像/快照删坏;删镜像必须走 crictl rmi。
